# ADR-018: 統計検定を自前実装し、外部実装で検証する

## ステータス

検証・候補選択補正まで実装済み（2026-08-19）。scipy照合で発見した連続値p値の`4 *`バグを修正し、候補生成側の選択バイアスには4分割の選択補正を追加した。無相関データの偽陽性テストも通過する。

## 背景

MeTheory は候補仮説の p 値を、完全順列検定・厳密二項検定・モンテカルロ順列検定
のフォールバックで計算している。いずれも `packages/domain/src/significance.ts`
に外部依存なしで実装されている。実行時依存は `personal-context-studio` と `pg`
のみ、開発依存は `@types/node` と `typescript` のみで、テストランナーも Node 標準の
`node:test` である。

これらの検定には成熟した実装が存在する。`scipy.stats.permutation_test` と
`scipy.stats.binomtest` は広く使われ、独立に検証されている。ここで使えないのは
MeTheory が Node 上で動くためであり、JavaScript の統計ライブラリには、
組み合わせ爆発のガードと決定論的モンテカルロ・フォールバックを備えた完全順列検定
が見当たらない。

リスクは具体的である。**順列検定は静かに失敗する。** 片側／両側の取り違え、
同値（tie）の数え方の誤り、`>=` であるべき箇所の `>`、モンテカルロ推定の
プラス1補正の欠落 — どれも「それらしい p 値」を返す。例外は出ず、テストも通る。
現在の実装には、自身の単体テスト以外に正しさの根拠がない。そしてその単体テストは、
実装を書いたのと同じ理解のもとで書かれている。

## 決定

自前実装を維持する。そのうえで、**外部実装との照合を手動で実行し、結果を記録する**
工程を追加する（`npm run verify` には組み込まない）。

1. 検証スクリプトが合成データの組を生成する。群サイズ 3〜20、効果量 0〜1、両方向。
2. 各ケースについて、`exactPermutationPValue` / `exactBinomialPValue` の p 値を、
   同一入力に対する `scipy.stats.permutation_test` / `scipy.stats.binomtest` と比較する。
3. 厳密計算の経路は浮動小数点誤差の範囲で一致すること。モンテカルロ経路は、
   設定した試行回数における標本誤差の範囲で一致すること。
4. 結果（実施日・scipy のバージョン・ケース数・最大差）を `docs/spec/` に記録する。
   **不一致は自前実装の欠陥として扱い、許容幅を広げて解決しない。**

`significance.ts` を変更したときは、この照合を再実行する。

## 代替案

- **JavaScript の統計ライブラリに依存する。** 却下。組み合わせ爆発のガードと
  決定論的フォールバックを備えた完全順列検定を提供するものが見当たらず、部分的な
  カバレッジのために依存を増やしても、残りの経路は未検証のままになる。
- **分析層を Python に移して scipy を直接使う。** 却下。PCS 統合契約、スナップショット
  検証、候補生成パイプラインはすべて TypeScript である。1 モジュールのために実行環境を
  分割すると、システム中で最も正しさに敏感な部分にプロセス境界と直列化の工程が増える。
- **外部照合なしで自前実装を受け入れる。** 却下。この製品の主張は「結論に根拠がある」
  ことである。独立実装と一度も突き合わせていない p 値は根拠を持たず、しかも失敗が
  表面化しない。
- **scipy との比較を CI に組み込む。** 現時点では却下。Node プロジェクトの検証
  パイプラインに Python ツールチェーンが必要になる。照合は変更時に実行し、結果を
  記録する運用とする。

## 影響

- 有意性判定の正しさの根拠が、実装単体ではなく**記録された外部照合**になる。
- 依存ゼロの姿勢が維持され、かつ「検討していない既定値」ではなく**意図した選択**になる。
- 照合の再実行には Python ツールチェーンが必要になる。実行時依存ではなく開発時の
  作業なので許容する。
- scipy と自前実装が食い違った場合、**反証されるまで自前実装が誤っている**とみなす。

## 撤回方法

照合で繰り返し不一致が見つかり、それが実装欠陥に帰着しない場合、または自前テストの
維持コストがプロセス境界のコストを上回った場合は、有意性判定層を Python サービスへ
移し、localhost 経由で呼び出す。バージョン付きのローカル境界が実用に耐えることは、
スナップショット契約が既に示している。
